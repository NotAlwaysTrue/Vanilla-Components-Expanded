# 制导弹实施记录

## 弹体、发射器与火控

`GuidedProjectile` 负责实体弹的转向和飞行状态。`GuidanceThruster` 是可选的同物品组件，沿弹体朝向施力，并以物品耐久作为燃料。转向本身保留当时的速率；弹体仍受游戏物理影响。推进器以 `fuelconsumption × throttle` 的速率消耗耐久，最后一次施力按剩余燃料比例折算。

需要外部指令时，给发射器或控制站添加 `GuidanceDataLink role="Publisher"`，给弹药添加同频道的 `role="Receiver"`。发布器上的 `CentralFireControl` 负责产生目标航迹和照射。手动瞄准和预设航路本身不需要火控扫描。仓库内的[测试物品 XML](../.Test/testItems.xml)包含同频道收发器、火控及推进器的组合示例。

| 弹体的 `<guidance mode="…">` | 转向依据 |
| --- | --- |
| `MLOS`、`SACLOS` | MLOS 追随操作员的光标位置。SACLOS 沿发布器到光标的瞄准线飞行，瞄准点靠近发射器时也可继续沿线向前。 |
| `ActiveImaging`、`ActiveInfrared`、`ActiveSonar` | 弹体自行扫描。成像与红外从弹体位置检查视线；红外还会过滤热成像隐藏和不可探测的角色。主动声纳可在墙后取得接触，弹体仍会撞墙。 |
| `DataLink` | 使用发布器的目标位置和速度，按距上次扫描的时间外推位置。发射方向取决于瞄准方向，航迹目标由火控选择。 |
| `SemiActiveLaser`、`SemiActiveSonar` | 跟随发布器指定的单个目标，照射类型必须匹配且信息仍有效。激光弹还要求从弹体到目标的视线畅通；被动声纳可提供可听目标的航迹，但不能提供半主动声纳照射。 |
| `Cruise`、`None` | Cruise 按航路点顺序飞行。None 适合无制导的滑行弹或推进弹。 |

可用 `mode="Cruise|DataLink|ActiveImaging"` 组合模式。有效的手动指令优先；中段可沿航路或使用航迹，末段按 `seekerpriority` 选取已启用的导引方式。`turnrate` 使用度/秒，`seekerrange` 和航路坐标使用游戏显示单位。扫描间隔、锁定时间、指令超时和最大寿命分别由 `scaninterval`、`seekerlocktime`、`commandtimeout`、`maxlifetime` 控制，单位均为秒。

## 扫描原点与遮挡

火控默认从物品位置搜索最近的有效接触。如果使用声纳，则从声纳或其连接的换能器位置扫描，并遵循声纳的探测范围、模式和方向。声纳查找顺序为同物品组件、相连设备、同艇最近的声纳。光标远近不会改变火控对候选目标的距离排序。

在 `276add7` 修复的双爬行者场景中，近目标被墙挡住，远目标可见。同一台火控可以把**近目标的航迹**发给数据链弹，同时把**远目标的照射**发给激光弹。近目标可见时共用首次扫描结果，只有近目标被挡住时才额外搜索最近的可见接触。如果发射器能看见指定目标、弹体却看不见，纯激光弹会失去制导，直到重新看见有效的指定目标。

同频道有多个发布器时，接收器优先使用发射自己的设备，其次选范围内符合连接条件的最近发布器。选源在检查航迹和照射内容之前，因此选中空闲发布器或照射类型不符的发布器时，不会自动尝试下一台。

## 航路与射手碰撞

- XML 的 `waypoints` 默认相对发射点，沿世界坐标轴偏移。`waypoints_in` 接受世界坐标，例如 `1000,2000;1400,2200`。`terminal_in` 的非零信号使弹体离开航路进入末段，`abort_in` 的非零信号立即结束飞行。旧的终止或中止信号不会作用于之后发射的弹体。
- 对发射时忽略射手碰撞且未开启 `DamageUser` 的弹体，每隔 0.5 秒比较弹体与射手主碰撞体、相连肢体的世界坐标及包围半径。连续两次采样都分离后才恢复对射手的碰撞；任一次重叠都会重新计数。最早约在发射后 1 秒生效，慢弹仍在射手身内时可继续安全离膛。两次采样之间短暂进出可能不会被记录。
- 单人和服务器负责飞行制导。联机手动瞄准由客户端限频上报，服务器核对操作者是否正持有并瞄准该物品，或正在操作该设备。

## 验证记录

Windows 1.15.33.2 单人测试已获玩家确认。直接复核的回归包括回头弹命中射手、预设折线路线按右—上—右飞行，以及有近目标遮挡时激光弹转向远处可见目标。玩家随后确认其余单人制导检查正常，包括主动搜索、匹配与错误频道、照射配对及滑行与推进的比较。

未单独记录单人开服结果。远端玩家操控、多个发布器或射手并发、丢包下的指令超时和专服位置同步仍待验证。
